## Git的使用方式
1. 命令行（Command Line）

· 这是什么：就是你刚刚打开的“终端”（黑框框），比如 Git Bash。你需要手动输入代码指令（比如 git add、git commit、git push）来告诉电脑做什么。
· 优点：最底层、最强大、最通用。网上所有的 Git 教程、所有的报错提示，都是基于命令行的。学会这个，你换任何电脑、用任何系统都能无缝使用。
· 缺点：门槛高，需要背指令，没有可视化的画面，对新手不太直观。
· 比喻：手动挡汽车。需要你自己挂挡踩离合，但真正懂车的人（老程序员）最爱用，因为操控感最强。

2. 图形化界面（GUI）

· 这是什么：专门为 Git 做的可视化软件。比如 GitHub Desktop（GitHub官方出的）、Sourcetree、TortoiseGit（小乌龟）等。你不需要敲代码，直接像用微信一样，用鼠标点“提交”、“拉取”、“合并”等按钮就行。
· 优点：直观、门槛极低。代码的修改历史、分支的走向都可以用图形（比如一条条的线）展示出来，对新手非常友好。
· 缺点：遇到复杂的操作（比如严重的代码冲突）时，图形界面可能处理不了，或者找按钮找半天。而且不同软件的界面长得不一样，没法通用。
· 比喻：自动挡汽车。傻瓜式操作，踩油门就走，非常适合新手。

3. IDE 插件/扩展

· 这是什么：IDE（集成开发环境）就是你用来写代码的软件，比如 VS Code、PyCharm、IntelliJ IDEA 等。这些写代码的软件本身自带了或者可以通过装插件来获得 Git 功能。你写完代码，直接点击编辑器侧边栏的按钮，就能把代码提交。
· 优点：最方便、程序员日常最常用。因为你不用在写代码的窗口和黑框框之间来回切换，无缝衔接，体验极佳。
· 缺点：本质上它也是封装的图形界面，遇到复杂冲突时，依然可能需要打开命令行去解决。
· 比喻：方向盘上的多功能按键。你手不用离开方向盘（不用离开写代码的软件）就能切歌、调音量，主打一个顺手。

## 初始化配置
```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@xxx.com"
git config --global credential.helper store
```

敲完之后，再敲 git config --global --list，如果弹出了一堆英文，只要里面有你刚才设置的 user.name 和 user.email，你的初始化配置就彻底大功告成了！

# 新建仓库
## 在终端中查看文件的命令
· ls -l：以“详细列表”形式显示（能看到文件大小、创建时间、权限等）。
· ls -la（或者 ll -a）：最常用的组合。既显示详细信息，又包含隐藏文件。
* 回车后，终端会输出类似这样的内容：

```text
.  ..  .git  test.txt
```

逐个解释：

1. .：代表“当前目录”（就是你现在待的这层文件夹）。
2. ..：代表“上一级目录”（也就是退回到上一层的文件夹）。这两个是系统自带的特殊符号，以后你会学到用 cd .. 退回上一级。
3. .git：你初始化生成的 Git 隐藏仓库！
4. test.txt：你建的普通文件。

## 在本地电脑新建仓库
1. 建个文件夹：在你电脑上找个合适的位置（比如 D 盘），新建一个文件夹，取名叫 my-first-repo（或者随便什么英文名）。
2. 打开终端：双击进入这个 my-first-repo 文件夹，在空白处右键选择 Open Git Bash here。
3. 初始化：在终端里敲下：
   ```bash
   git init
   ```
   (敲完回车，你会发现终端路径后面多了一个绿色的 (main)，代表本地仓库建好了。)
* git init 后面可以指定仓库根目录
* git clone 后面跟远程仓库名称可以复制远程仓库

# Git 的工作区域和文件状态
📦 Git 的三大核心工作区域（一个完整的购物流程）

1. 工作区（Working Directory）—— “超市货架”

· 是什么：就是你电脑里能直接看到的文件夹（比如你截图里的 learning_note 文件夹）。
· 你在干嘛：你在这里新建文件、修改代码、删除内容。
· 特点：这里的内容是你随时在变的，Git 还在盯着你，但还没把它们存进保险箱。

2. 暂存区（Staging Area / Index）—— “购物车”

· 是什么：它是个看不见的隐藏区域，其实就是我们之前说的 .git/index 文件。
· 你在干嘛：你敲 git add 命令时，就是把修改好的文件放进购物车。你可以挑挑拣拣，放进去几个，再拿出来几个。
· 特点：代表你“准备提交”的内容。购物车里的东西随时可以反悔（用 git restore --staged 拿出来）。

3. 本地仓库（Local Repository）—— “收银台/你的家”

· 是什么：就是 .git/objects 里面的那些压缩文件。
· 你在干嘛：你敲 git commit 命令，就是把购物车里的东西结账打包，形成一条不可磨灭的历史记录（快照）。
· 特点：存进这里的东西，就正式成为版本历史了，非常安全。

(补充第四区域：远程仓库（Remote）—— “快递站”，用 git push 把你家（本地仓库）的东西寄到 GitHub 去。)

---

🚦 Git 的四种文件状态（配合 git status 查看）

当你在“工作区”新建或修改了一个文件，Git 会盯着它，给它贴上不同的标签。你可以随时敲 git status 来查岗。

1. 未跟踪（Untracked）—— “陌生人”

· 情况：你刚在文件夹里新建了一个文件（比如之前说的 text.txt），从来没对它执行过 git add。
· 表现：git status 里显示为红色，提示 Untracked files。

2. 已修改（Modified）—— “变心的人”

· 情况：文件以前已经被 Git 管着了（提交过），但你现在又打开它改了里面的字，还没放进暂存区。
· 表现：git status 显示为红色，提示 Changes not staged for commit。

3. 已暂存（Staged）—— “购物车里的人”

· 情况：你改完了文件，敲了 git add .。它从工作区被塞进了暂存区。
· 表现：git status 显示为绿色，提示 Changes to be committed（准备提交的更改）。

4. 已提交 / 未修改（Committed / Unmodified）—— “老实待着的人”

· 情况：你敲了 git commit，购物车被清空了，所有东西都存进了本地仓库。
· 表现：git status 会提示 nothing to commit, working tree clean（工作区干净，没有东西需要提交）。

---

🔄 状态是怎么转换的？（核心流程图）

你可以把下面这条线刻在脑子里，这就是你以后每天写代码的循环：

1. 你新建了一个文件 ➡️ 状态：未跟踪（红）
2. 你敲了 git add ➡️ 状态变为：已暂存（绿）
3. 你敲了 git commit ➡️ 状态变为：已提交（干净了）
4. 你再次打开文件改了几个字 ➡️ 状态变为：已修改（红）
5. 你想把修改存下来，再敲 git add ➡️ 回到状态：已暂存（绿）...

# 问题
## .git文件夹里面是什么
我们可以把 .git 文件夹想象成一个“公司档案室”，里面主要由以下几大部门组成：

1. objects 文件夹（档案库）

· 作用：存放你所有代码的真实内容（快照）。
· 里面是什么：你每次提交（Commit）的代码，全都被压缩打包成了二进制文件，以极长的乱码（哈希值）命名，存在这个文件夹里。比如你写了一句 Hello World，它就会被压缩成一个文件放在这。
· 特点：它非常聪明，如果你两张照片（版本）只改了一个字，它只存这改动的部分，绝不重复存没变的部分，这就是它节省空间的原因。

2. refs 文件夹 和 HEAD 文件（导航系统）

· 作用：记录指针，告诉你“现在在哪”以及“历史轨迹”。
· HEAD 文件：你每次看到终端里绿色的 (main)，就是它在这里记录着。它的内容其实就是一句话：“当前正在指向 refs/heads/main”。
· refs/heads：这里存放着所有分支（Branch）的信息。比如 main 分支、dev 分支。这些文件里面没有代码，只有一串指纹（哈希值）。这就好比书的目录，告诉你最新的一页在 objects 档案库的哪个位置。

3. index 文件（暂存区 / 购物车）

· 作用：记录你刚刚敲了 git add 的文件。
· 比喻：你去超市买东西，index 就是你的购物车。你把要结账的东西放进去（add），等你确认无误了，再一起推给收银员（commit）。这个文件是二进制格式的，你看不懂，但 Git 靠它来决定下一次要打包存哪些文件。

4. config 文件（配置文件）

· 作用：记录当前这个仓库的专属设置。
· 里面是什么：你在这个文件夹里设置的“局部”用户名、邮箱、远程仓库的 URL 地址（就是你之前敲的 git remote add）等，都白纸黑字地写在这个文件里，可以直接用记事本打开看。

5. logs 文件夹（监控录像）

· 作用：记录你的所有“危险操作”。
· 里面是什么：你每一次切换分支、提交、合并、甚至“毁尸灭迹”地强行重置，它都会记上一笔。Git 之所以被称为“后悔药”，就是因为你哪怕把分支删了，靠着 logs 里的记录（git reflog 命令），也能把你丢失的代码找回来。这是程序员的保命符。

## 移动文件夹是否有影响
这个问题要分两种情况来看，因为“移动文件夹”在电脑操作系统里和在 Git 眼里，概念是不一样的。

我们用“搬家”来打个比方：

情况一：把整个 learning_note 文件夹（连同里面的 .git）一起搬走

👉 答案：Git 完全不受影响，依然正常工作。

假设你之前在 D:\meng\learning_note，现在你用鼠标把它剪切，粘贴到了 E:\我的项目\learning_note。

· 只要那个隐藏的 .git 文件夹跟着一起搬过去了。
· 你在这个新位置的文件夹里右键打开 Git Bash，敲 git log，你之前所有的历史记录、分支、配置，全都在！
· 比喻：你把一个装着保险箱（.git）的整个房间，原封不动地搬到了另一栋楼。Git 只认那个保险箱，不认房间在几楼。

⚠️ 唯一的改变：Git 里记录的“远程仓库地址”没变，所以你依然可以正常 git push。但如果你的项目里写了绝对路径（比如 D:\...），你需要自己改一下代码里的路径。

---

情况二：在 learning_note 文件夹内部，把某个文件或子文件夹挪了位置

👉 答案：Git 不会“自动”帮你提交更改，你需要手动确认。

假设 learning_note 里原来有个文件叫 笔记.md，你把它挪到了 learning_note/日记/笔记.md。
这时候，你敲 git status，Git 会这样告诉你：

· 红字显示：deleted: 笔记.md（你删除了原位置的文件）
· 红字显示：Untracked files: 日记/笔记.md（你新建了一个文件）

Git 实际上是很笨的，它不知道你是“移动”了文件，它以为你“删除”了旧文件，又“新建”了一个一模一样的文件。

你需要怎么做？
老老实实敲：

```bash
git add .
git commit -m "移动了笔记文件的位置"
```

这样，Git 就会把这次移动记录到历史里。
(其实如果你想保留移动的历史，最好在终端里用 git mv 旧路径 新路径 命令来移动，但直接用鼠标拖拽再用 add/commit 也完全没问题，殊途同归。)

---

🚨 极其危险的操作（千万别做）：

如果你在移动文件夹时，只把里面的文本文件复制/剪切走，把隐藏的 .git 文件夹留在了原地，或者在移动途中把它删了。
那你移动后的文件夹就只是一个普通文件夹了，它失去了所有的“时光机”超能力，变成了凡人。所有的历史记录全部丢失。

💡 总结建议：
如果你觉得 learning_note 现在放的位置不好，想换个盘、换个目录：

1. 直接去电脑资源管理器里，把整个文件夹（连同隐藏的 .git）一起剪切走。
2. 到了新地方粘贴。
3. 在新文件夹里右键打开 Git Bash，敲个 git status。只要显示 working tree clean（干净），就说明搬家完美成功！
