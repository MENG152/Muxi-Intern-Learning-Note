这张图展示的是 Go 语言里发送 POST 请求（客户端）的“终极完全体”形态。

你之前学过 http.Get，那是极其简单的 GET 请求。但在木犀的机试（网络请求题/综合题）中，如果你需要向后端提交复杂数据（比如 JSON），或者需要伪造特定的请求头，就必须用到这张图里的代码。

我结合你熟悉的 Python 知识，把图里的 4 个步骤拆解给你看，并指出考场上绝对不能踩的坑。

---

🟢 步骤 1：构建请求 (构建你想发出去的信)

```go
request, err := http.NewRequest(
    "POST",
    "https://example.com",
    bytes.NewBuffer(data), // data 是字节数组
)
if err != nil {
    panic(err)
}
```

· 为什么不用 http.Post？ 因为 http.Post 只能传最简单的数据，没法加复杂的请求头。http.NewRequest 是万能的，你可以指定请求方法（GET/POST/PUT/DELETE等）。
· bytes.NewBuffer(data) 是啥？ 这是新手最容易卡住的地方。http.NewRequest 的第三个参数要求是一个 io.Reader（数据流）。如果你要把一个字符串或者 JSON 发过去，通常要先用 json.Marshal 转成字节数组 []byte，然后再套一层 bytes.NewBuffer 把它变成数据流。
  · Python对比：在 requests 里，你直接写 requests.post(url, json=data) 就行了，Python 帮你把脏活累活全干了。Go 必须自己一步步来。

---

🟢 步骤 2：添加请求头 (贴上标签)

```go
request.Header.Set("Content-Type", "application/json")
```

· 极其重要！ 如果你要发 JSON 数据，必须加上这句。这就好比你在快递盒子上贴个标签告诉对方“里面装的是 JSON”。如果对方（服务端）没收到这个标签，可能直接解析失败，返回 400 错误。

---

🟢 步骤 3：执行请求，接收响应 (把信寄出去)

```go
client := &http.Client{} // 创建一个 Client
response, err := client.Do(request)
if err != nil {
    panic(err)
}
defer response.Body.Close()
```

· client := &http.Client{}：虽然 Go 也有像 http.DefaultClient 这样的现成客户端，但推荐自己建一个，因为以后你可以在这里设置超时时间（Timeout）。
· client.Do(request)：这个才是真正把“信”寄出去的动作。
· defer response.Body.Close()：你刚学过的保命神符！ 拿到响应后立刻 defer，防止内存泄漏。

---

🟢 步骤 4：解析响应 (拆快递)

```go
value := response.Header.Get("Content-Type") // 获取响应头
body, err := io.ReadAll(response.Body)       // 读取响应体
if err != nil {
    panic(err)
}
// 后面通常会跟 json.Unmarshal(body, &目标结构体)
```

· 拿到了 response 后，你可以看它的头（Header），也可以看它的内容（Body）。读取 Body 依然是用你之前学过的 io.ReadAll。

---

💡 木犀考场避坑警告（千万注意！）

图里的代码写得好，但有一处在正式的后端项目或机试中绝对不能用的东西：
panic(err) —— 这个词的意思是“程序直接崩溃”。在本地做实验可以，但在机试考试里，如果请求失败了你直接 panic，你的 Web 服务就当场死机了。考试遇到 err != nil，应该用 fmt.Println 打印错误并 return。

---

🎯 考前必背的极简模板（直接抄进去改）

如果在考场上，题目让你“向某个 API 发送一段 JSON 数据”，不要当场推导，直接把这个模板默写出来：

```go
// 假设你要发这些数据
reqData := map[string]string{"name": "muxi", "type": "backend"}
jsonData, _ := json.Marshal(reqData) // 先转成 byte

// 1. 构建
req, _ := http.NewRequest("POST", "http://对方地址", bytes.NewBuffer(jsonData))
req.Header.Set("Content-Type", "application/json")

// 2. 发送
client := &http.Client{}
resp, err := client.Do(req)
if err != nil {
    fmt.Println("请求失败:", err)
    return
}
defer resp.Body.Close()

// 3. 读取
body, _ := io.ReadAll(resp.Body)
fmt.Println("收到回复:", string(body))
```

这就是木犀后端网络请求题的标准答案！你现在的 Python 思维要适应一下这种“一步拆成三步写”的啰嗦感，习惯了之后你会发现它的控制力非常强。

第一题：获取 wjj 学长的 hint（接口逆向）

解题思路：
提示说“cbw线的接口结构与wjj线同构”。这意味着你需要使用浏览器的开发者工具（F12）。

1. 打开 http://8.162.10.6:8080/。
2. 按 F12 打开开发者工具，切换到 Network（网络） 面板。
3. 在网页上点击与 cbw 相关的按钮或链接。
4. 观察抓到的网络请求（通常是 XHR 或 Fetch）。你会看到请求的 URL 结构、请求方法（GET/POST）以及携带的参数（Payload）。
5. 假设你看到请求是 GET /api/get_hint?name=cbw，那么你只需要把 cbw 换成 wjj 就能拿到提示。

自动化尝试代码（你可以运行这个脚本，或者根据F12抓包结果修改）：

```python
import requests

def get_wjj_hint():
    base_url = "http://8.162.10.6:8080"
    
    # 【注意】这里需要你通过 F12 抓包找到真实的接口路径
    # 假设 cbw 的接口是 /api/hint?user=cbw，那么 wjj 就是 /api/hint?user=wjj
    # 请根据你的实际抓包情况修改下面的 URL 和参数
    target_url = f"{base_url}/api/hint" 
    params = {
        "user": "wjj"  # 将 cbw 替换为 wjj
    }
    
    headers = {
        "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"
    }

    try:
        # 如果抓包发现是 POST 请求，请改用 requests.post 并构建 data 或 json 参数
        response = requests.get(target_url, params=params, headers=headers, timeout=5)
        print("状态码:", response.status_code)
        print("返回内容:", response.text)
        
        if response.status_code == 200:
            print("\n✅ 成功拿到数据！请提交这段内容作为 hint。")
        else:
            print("\n❌ 请求失败，请检查接口路径或请求方法是否正确。")
            
    except Exception as e:
        print(f"请求出错: {e}")
        print("提示：如果无法访问，请确保你处于实验室网络或校园网环境下。")

if __name__ == "__main__":
    get_wjj_hint()
```

第二题：爬取 demosite 所有帖子内容

解题思路：
这两个网站（demosite1 和 demosite2）是经典的爬虫练习站。通常这种网站的首页有一个帖子列表，每个帖子有一个链接。你需要做两件事：

1. 解析首页，拿到所有帖子的 URL。
2. 遍历这些 URL，进入详情页提取文本内容。

完整爬虫代码：

```python
import requests
from bs4 import BeautifulSoup
from urllib.parse import urljoin
import time

def crawl_demosites(base_url):
    print(f"\n{'='*50}\n开始爬取: {base_url}\n{'='*50}")
    
    headers = {
        "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"
    }
    
    try:
        # 1. 请求首页
        response = requests.get(base_url, headers=headers, timeout=10)
        response.raise_for_status() # 检查请求是否成功
        response.encoding = response.apparent_encoding # 解决中文乱码
        
        # 2. 解析首页，提取帖子链接
        soup = BeautifulSoup(response.text, 'lxml')
        
        # 【注意】这里的 'a' 标签和 'href' 是通用的。
        # 实际可能需要过滤掉导航栏、页脚的无用链接。你可以通过 F12 观察帖子链接的特征。
        # 假设帖子链接都在 <a> 标签中，或者带有特定的 class（如 class_="post-title"）
        post_links = []
        for a_tag in soup.find_all('a', href=True):
            link = a_tag['href']
            # 过滤掉明显的非帖子链接（如 #, javascript:void(0) 等）
            if link.startswith('#') or 'javascript' in link:
                continue
                
            # 拼接成完整的绝对路径
            full_url = urljoin(base_url, link)
            
            # 【重要】通常我们需要过滤一下，只保留详情页的链接
            # 假设详情页链接包含 '/post/' 或者 '/article/' 等特征，请根据实际情况修改
            if full_url not in post_links and full_url != base_url:
                post_links.append(full_url)

        print(f"共发现 {len(post_links)} 个可能的链接，开始遍历获取内容...\n")
        
        # 3. 遍历访问每个链接，提取内容
        for i, post_url in enumerate(post_links, 1):
            try:
                post_resp = requests.get(post_url, headers=headers, timeout=5)
                post_resp.encoding = post_resp.apparent_encoding
                post_soup = BeautifulSoup(post_resp.text, 'lxml')
                
                # 【注意】这里需要根据实际网页结构修改！
                # 假设正文在 <div class="content"> 或 <article> 中
                # 如果没有找到，你可以 print(post_soup.prettify()) 看看源码结构
                content_div = post_soup.find('div', class_='content') or post_soup.find('article') or post_soup.find('div', id='content')
                
                if content_div:
                    title = post_soup.title.string.strip() if post_soup.title else "无标题"
                    content = content_div.get_text(strip=True, separator='\n')
                    
                    print(f"[{i}/{len(post_links)}] 标题: {title}")
                    print(f"链接: {post_url}")
                    print(f"内容:\n{content}")
                    print("-" * 40)
                else:
                    print(f"[{i}/{len(post_links)}] 未找到正文内容，链接: {post_url} (可能需要调整解析规则)")
                
                # 爬虫礼貌延时，防止被封 IP
                time.sleep(0.5) 
                
            except Exception as e:
                print(f"爬取 {post_url} 失败: {e}")
                
    except Exception as e:
        print(f"获取首页 {base_url} 失败: {e}")

if __name__ == "__main__":
    # 要爬取的两个目标网站
    sites = [
        "https://demosite1.muxixyz.com/",
        "https://demosite2.muxixyz.com/"
    ]
    
    for site in sites:
        crawl_demosites(site)
```

代码调整指南（必读）

由于我看不到实际网站的 HTML 代码，上面代码中提取正文的 post_soup.find('div', class_='content') 是猜测的。

1. 如果运行后发现“未找到正文内容”，请在浏览器打开其中一个帖子。
2. 右键点击帖子正文，选择“检查（Inspect）”。
3. 找到包裹正文的 HTML 标签（比如 <div class="article-body">），然后把代码里 find 的参数改成对应的 class 或 id 即可。
